# Component Catalogue

Status legend: **Implemented** (in Phase 1, tested) · **Foundation** (contracts and core
mechanics implemented and tested; full capability in a later phase) · **Deferred**
(not implemented; target phase given).

| # | Component | Crate / module | Phase 1 status | Responsibility (as implemented) | Key interfaces | Security boundary |
|---|---|---|---|---|---|---|
| 1 | Core Runtime | `eaeh-core`, `eaeh-runtime::harness` | Implemented | Typed ids, error taxonomy, principals/scopes, risk & autonomy, secrets, clock, trace context; composition root | `Harness`, `HarnessBuilder`, `HarnessError` | Composition root is the only place concrete implementations are wired |
| 2 | Hybrid Orchestration Engine | `eaeh-workflow::engine`, `eaeh-runtime::executor` | Implemented | Deterministic engine validates and executes; planner/agents propose | `WorkflowEngine`, `Planner`, `TaskExecutor` | Planner output is `Untrusted`, validated against definition + policy |
| 3 | Workflow Management | `eaeh-workflow` | Implemented | Declarative definitions (validated), durable instances, transitions, checkpoints, retry/timeout/cancel, recovery. Phase 3: request-changes revisions bounded by `max_revisions`, bindings, quality gates on states, bundles, trace-link recording. | `WorkflowDefinition`, `drive`, `recover`, `cancel` | Optimistic concurrency; gate checks independent of graph |
| 4 | Agent Runtime & Management | `eaeh-agents` (`runtime`, `external`) | Implemented | Versioned definitions, registry, discovery (smallest effective), dynamic instantiate/execute/terminate, autonomy. ADR-0025: execution modes, plus external-AI hand-off (prepare package → suspend → governed task tools → validate submission) | `AgentRegistry`, `AgentRuntime`, `ExecutionMode` | Agent principals are role-less and project-bound; client tool calls run as the agent; operators only (`task.execute_external`) |
| 5 | Agent Communication | `eaeh-agents::runtime::delegate` | Foundation | Typed delegation + result messages (persisted), authorization, allow-list, depth, cycle, fan-out, duplicate checks | `AgentRuntime::delegate` | No free-form agent-to-agent channel |
| 6 | Execution Environment Manager | `eaeh-isolation` | Implemented | Provider abstraction with declared capabilities; restricted process; OCI container | `ExecutionProvider`, `ProviderRegistry` | Selection refuses instead of downgrading |
| 7 | Hook Framework | `eaeh-extensibility::hooks` | Implemented | 42 typed hook points, ordering, filters, timeouts, failure policies, enable/disable, API versioning | `Hook`, `HookRegistry` | Runs after mandatory controls; vetoes only restrict |
| 8 | Middleware & Interceptors | `eaeh-extensibility::{middleware, interceptor}` | Implemented | Ordered pipelines; value interceptors (redaction, size) | `Pipeline`, `Middleware`, `InterceptorChain` | Not used for mandatory controls |
| 9 | Event Management | `eaeh-events` | Implemented | Typed versioned envelopes, transactional outbox, at-least-once dispatch, retry/backoff, dead-letter, ordering | `EventEnvelope`, `EventDispatcher`, `EventSubscriber` | Payloads carry identifiers, not secrets |
| 10 | Plugin & Extension Mgmt | `eaeh-extensibility::plugin`, `eaeh-runtime::extensions` | Foundation | Manifests, digest + ed25519 verification, lifecycle, grants; trusted in-process host only | `PluginRegistry`, `InProcessExtension` | Signatures ≠ isolation; WASM/external hosts deferred |
| 11 | Tool Gateway & Registry | `eaeh-tools` | Implemented | Versioned registry with JSON-Schema contracts; governed gateway; built-in `fs.read/list/write`, `exec.run` | `Tool`, `ToolRegistry`, `ToolGateway` | Sole path to system capabilities |
| 12 | Context Engineering | `eaeh-intelligence::context` | Implemented (Phase 2: governed knowledge, classification) | Trust-ordered assembly, scope filtering, expiry, conflict detection, token budget, fencing, redaction, snapshots | `ContextAssembler`, `ContextItem` | Untrusted content cannot become instructions (type-level) |
| 13 | Prompt Management | `eaeh-intelligence::prompt` | Implemented | Versioned templates with typed variables, draft/approved/retired, rollback, platform prompt loading | `PromptRegistry`, `PromptTemplate` | Only registered templates produce instructions |
| 14 | LLM Provider & Model Mgmt | `eaeh-intelligence::{model, client, embedding}`, `eaeh-provider-anthropic` | Implemented (Phase 2) | Registry, routing, fallback, circuit breaker, budgets, usage/version/skill/knowledge recording; **egress policy** on classification; `EmbeddingProvider`; opt-in Anthropic adapter | `ModelProvider`, `ModelClient`, `EmbeddingProvider`, `AnthropicProvider` | Credentials only via secrets provider; `restricted` never egresses (also for external-AI hand-offs); adapter verified against mock only; no provider registered in `external_ai` mode |
| 15 | Enterprise Knowledge Mgmt | `eaeh-knowledge` | Implemented (Phase 2) | Sources, versioned documents, quarantine, approval of standards, lifecycle/purge, FTS5 + vectors, hybrid retrieval, scopes/ABAC, freshness, conflicts, mandatory standards, `knowledge.search` | `KnowledgeService`, `KnowledgeSearchTool` | Tenant/scope/classification filtered in SQL; sole producer of standard instructions |
| 16 | Skills Management | `eaeh-skills` | Implemented (Phase 2) | Versioned, approved skills with contracts, dependencies, required knowledge/tools; permission-preserving deterministic binding | `SkillRegistry` | Skills never grant tools/autonomy; sole producer of skill instructions |
| 17 | Validation Framework | `eaeh-validation` | Implemented | Schema contracts, validator trait, severities/evidence, quality gates (fail-closed; semantic never sole basis). Phase 3: domain validators `requirements.set`, `architecture.hld`, `architecture.lld`; gates `requirements`/`hld`/`lld` run by the workflow engine and in the agent correction loop. | `Validator`, `ValidationEngine`, `QualityGate`, `CompiledSchema` | Remote `$ref` disabled |
| 18 | Feedback & Correction Engine | `eaeh-agents::runtime` | Foundation | Bounded output-correction loop with platform feedback; loop detection. Phase 3: deterministic validator findings drive bounded agent correction. | `CorrectionAttempts` budget | Feedback is platform-generated task input |
| 19 | Workspace & Artifact Mgmt | `eaeh-workspace` | Implemented | Per-scope workspaces, path confinement, locks, atomic writes; versioned content-addressed artifacts with provenance. Phase 3: multi-file bundles bound by a manifest hash; provenance records standards and quality gates. | `WorkspaceManager`, `Workspace`, `ArtifactStore` | Traversal/symlink rejection, `O_NOFOLLOW`, scope-checked |
| 20 | Governance & Policy Engine | `eaeh-governance::policy` | Implemented | Deterministic rule engine, levels, conflict resolution, decision records | `PolicyEngine`, `RuleEngine` | Default deny, deny-overrides |
| 21 | Human Approval Mgmt | `eaeh-governance::approval` | Implemented | Requests, decisions, SoD, artifact-hash binding, supersession, history. Phase 3: `request_changes` (workflow gates only, comments required). | `ApprovalManager` | Human + role + scope + not-author, enforced in-component |
| 22 | Execution Budget & Supervision | `eaeh-governance::budget`, `eaeh-runtime::supervision` | Implemented | Durable atomic budgets (fail closed); stalled-task & repeated-failure escalation | `BudgetLedger`, `Supervisor` | Child budgets ≤ parent |
| 23 | Observability & Audit | `eaeh-store::audit`, `eaeh-runtime::observability` | Implemented | Hash-chained audit + verification; redacting JSON logs; event-derived metrics; health. Phase 3: traceability store (`trace_links`) of approved artifacts; `/v1/traceability`. | `Db::audit*`, `verify_audit_chain`, `Metrics` | Audit details redacted before hashing |
| 24 | Project & Tenant Mgmt | `eaeh-governance::identity`, `eaeh-core::scope` | Foundation | Tenants, projects, scope on every entity, scope checks in authz and queries | `Scope`, `IdentityService` | Cross-tenant access impossible via API (tenant from principal) |
| 25 | Engineering Integration Mgmt | `eaeh-engineering` (design tools) | Partial (Phase 3: requirements & architecture design tools; Git/CI/CD Phase 6+) | Governed read-only tools `brd.sections`, `requirements.render`, `architecture.render`, `design.check`; requirement/HLD/LLD models in `eaeh-requirements`, `eaeh-architecture` | `register_validators`, `default_gates` | Pure design crates cannot reach storage/models/agents (fitness) |
| 26 | API, CLI & User Interaction | `eaeh-api`, `eaeh-cli` | Implemented | `/v1` HTTP API (auth, authz, errors, pagination, rate limits, body limits); `eaeh` CLI; developer experience (ADR-0024, ADR-0025): identity profiles, `project init`/`readiness` (execution mode, clients, delivery), approval review queue, activity runs (`requirements`/`design`/`deliver`), `eaeh task` hand-offs, `eaeh mcp` server for Claude Code and GitHub Copilot | `router`, `eaeh` | Bearer tokens; CLI token via env var |
